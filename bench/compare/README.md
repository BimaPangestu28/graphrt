# graphrt vs Python agent stacks

A reproducible comparison of graphrt with [LangGraph](https://github.com/langchain-ai/langgraph)
(plus `langchain-openai` for the model node) and plain LangChain LCEL runnables.
Results and discussion: [docs/benchmarks.md](../../docs/benchmarks.md#graphrt-vs-python-agent-stacks).

```sh
bench/compare/run.sh            # host measurements, ~15 minutes
bench/compare/run.sh --docker   # also cold start + peak RSS in a Linux container (1 CPU, 1 GiB)
bench/compare/run.sh --quick    # 5 hyperfine runs instead of 30 (smoke test)
```

Needs `cargo`, `hyperfine`, Python 3.11 (`PYTHON=...` to pick another
interpreter) and, for `--docker`, Docker. Results land in
`bench/results/<date>-<host>-vs-python.{json,md}`. The script reuses
`bench/compare/.venv` and `bench/compare/target`; delete both when done.

## What runs

Both sides run the same graph shapes against the same local fake
OpenAI-compatible server and receive the same bytes.

| Shape | graphrt | Python |
| --- | --- | --- |
| `llm3`: 3 nodes, one model call | [`workflows/llm3.yaml`](workflows/llm3.yaml): `start -> llm -> end` | `prepare -> llm -> finish` (`StateGraph`, async nodes, `ChatOpenAI(streaming=True).ainvoke`); LCEL: `prompt \| ChatOpenAI \| StrOutputParser` |
| `chain-N`: N passthrough nodes in a line | `variable-aggregator` nodes, generated by [`workflows/generate.py`](workflows/generate.py) | `StateGraph` with N nodes returning `{"x": state["x"]}`; LCEL: `RunnableSequence` of N `RunnableLambda`s |
| `fanout-N`: N parallel passthrough branches + a join | same generator | `StateGraph`, `START -> p_i`, `add_edge([p_0..p_N-1], "join")`; LCEL: `RunnableParallel` + `RunnableLambda` |

Python definitions: [`python/graphs.py`](python/graphs.py). N is 10 and 1,000.

| File | Role |
| --- | --- |
| `rust/src/bin/fakeoai.rs` | Fake `/v1/chat/completions`: optional fixed delay, then an SSE body of 10 text deltas, `stop`, `[DONE]`. HTTP/1.1 keep-alive, 2 Tokio threads. |
| `rust/src/bin/graphrt_driver.rs` | In-process graphrt: compile once, run sequentially (`seq`) or with C in flight (`conc`). Uses the same `graphrt-core` engine and `graphrt-llm` OpenAI provider as the CLI. |
| `python/driver.py` | The Python counterpart: `once` (cold start), `seq`, `conc`. |
| `measure.py` | Runs everything: hyperfine, `/usr/bin/time`, the drivers, footprint. Starts and stops the fake server itself. |
| `report.py` | Turns the JSON into the Markdown tables. |
| `docker/` | Linux image (python:3.11-slim + GNU time + hyperfine + static musl graphrt) for the container measurements. |

## Metrics

1. **Cold start to first result**: `graphrt run <workflow>` vs `python driver.py once <framework> <shape>`,
   full process start to exit, hyperfine with 3 warm-up runs (so `.pyc` files and the page cache are warm).
   Context rows: `python -c pass`, the imports alone, `graphrt version`.
2. **Peak RSS**: `/usr/bin/time -l` (macOS) or GNU `/usr/bin/time -v` (Linux) on the same
   commands, median of 5; also of each throughput process.
3. **Per-node orchestration overhead**: warm, in-process, graph compiled once; median run time of
   `chain-N` / `fanout-N`, per node and marginal ((t₁₀₀₀ − t₁₀) / 990).
4. **Concurrent throughput**: `llm3` with C ∈ {1, 10, 100, 1,000} runs in flight and a 50 ms
   server delay (ideal = C / 0.05 s), plus C = 100 with no delay (CPU-bound).
5. **Install footprint**: `min-size` binaries vs the venv (`site-packages` without pip) and its
   distribution count; with `--docker`, image sizes.

## Fairness rules

- Same fake server, same latency, same response bytes; the model is streamed on both sides
  (`streaming=True` in `ChatOpenAI`, graphrt's `llm` node always streams).
- Python at its idiomatic best: graphs compiled once and reused, async nodes with `ainvoke`
  on one event loop, one shared `ChatOpenAI` client (connection pooling), no checkpointer,
  `debug` off, `max_retries=0`. LangSmith tracing is disabled explicitly
  (`LANGCHAIN_TRACING_V2=false`, `LANGSMITH_TRACING=false`, API keys removed from the environment).
  For the CPU-only shapes we also measure sync `invoke` with sync nodes (`langgraph-sync`),
  which avoids the event loop and is faster for LangGraph; the docs quote the better of the two.
- graphrt: release (`min-size`) CLI with default features, `--no-default-plugins`,
  telemetry off. `--allow-private-network` is needed because the fake server is on loopback.
- Concurrency: Python gets one event loop (CPython runs Python code on one core); graphrt is
  reported both on all cores and on one worker thread.
- Warm-up everywhere: 3 hyperfine runs, 20 in-process runs, one throughput round.

## Not measured

Real providers (network latency dominates every real run and makes the orchestration
differences below small in absolute terms), tool calls, checkpointing/persistence, uvloop,
PyPy, free-threaded CPython, multi-process Python servers (e.g. several uvicorn workers).
